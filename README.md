# bitrix24_aisearch — гибридный AI-поиск по порталу Bitrix24

Модуль `mtai.aisearch` переводит главный поиск портала на гибридную выдачу.
Найденные элементы выглядят как обычные результаты и попадают в те же
секции подсказки: сделки, контакты, компании, лиды, сотрудники, инфоблоки.

Это отдельное решение. Своих копий поиска и LLM в нём нет: сущности и
права берёт [mtai.opensearch](https://github.com/MTai88/bitrix24_opensearch),
модель и базу знаний — [mtai.aiagent](https://github.com/MTai88/bitrix24_aiagent).

Оба режима включаются и выключаются в настройках. Если выключить оба,
портал работает так же, как с одним `mtai.opensearch`.

## Что меняется в поиске

Штатный `crm.api.entity.search` по-прежнему перехватывает JS-патч
`mtai.opensearch`. Дальше запрос идёт так:

1. **BM25** — морфологический поиск OpenSearch (имена, телефоны, номера).
2. **kNN** — поиск по смыслу. Вектор считается по тексту тех же документов,
   что уже лежат в индексе opensearch: те же сущности и те же поля.
   В подсказку такой документ попадает, только если в названии есть общее
   слово с запросом («поставки» и «Поставка продукта»). Соседи без общего
   слова не добавляются.
3. **RRF** — обе выдачи сливаются по рангам.
4. Дальше `mtai.opensearch` проверяет права и оформляет элементы.
   Если эмбеддер не ответил за таймаут, OpenSearch недоступен или
   гибридный режим выключен, остаётся исходная выдача.

Отдельного блока в подсказке нет. Шапка сама раскладывает CRM-элементы
по секциям, патч opensearch — сотрудников и инфоблоки.

## Зависимости

| Модуль | Зачем | Версия |
|--------|--------|--------|
| `mtai.opensearch` | BM25, права, события индекса | 1.3.0+ (события `onSearchHits`, `onAfterIndexDocument`, `onAfterDeleteDocument`) |
| `mtai.aiagent` | эмбеддинги, чат, база знаний | 0.3.1+ (`Config::withHttpTimeout`, иначе таймаут запроса в шапке не укорачивается) |
| OpenSearch 2.9+ / 3.x | kNN (движок lucene, входит в стандартный образ) | тот же кластер, что у opensearch |

Для поиска по смыслу нужен провайдер с настоящими embeddings
(OpenAI-совместимый, YandexGPT, GigaChat). Мок и встроенный
`HashEmbedder` прогоняют конвейер, но сравнивают слова, а не смысл.
Настройки эмбеддера — в `mtai.aiagent` (`llm_embedding_provider`).

## Установка

1. Скопируйте каталог `mtai.aisearch/` в `<портал>/local/modules/`.
2. Установите модуль: Настройки → Настройки продукта → Модули.
   Если `mtai.opensearch` или `mtai.aiagent` не установлены, установка
   остановится.
3. Откройте «Настройки → AI-поиск: векторы» (или
   `cli/reembed.php`) и посчитайте векторы.
4. В настройках модуля включите «Гибридный поиск» и, если нужно,
   «Ответ AI».

Смена провайдера или модели эмбеддингов меняет размерность вектора.
Индекс нужно пересоздать и векторы пересчитать — об этом пишет статус
на вкладке настроек.

### CLI

```bash
docker compose exec php php /var/www/html/local/modules/mtai.aisearch/cli/reembed.php
docker compose exec php php /var/www/html/local/modules/mtai.aisearch/cli/reembed.php --keep
```

Живые изменения сущностей в очередь эмбеддинга попадают сами
(события индекса opensearch). Агент модуля разбирает очередь раз в минуту.
Сохранение карточки CRM эмбеддинга не ждёт.

## Настройки

**Гибридный поиск.** Включение, имя индекса (по умолчанию
`bitrix24_morpho_vectors`), веса BM25/kNN и `k` для RRF, размер kNN и
`min_score`, минимальная длина запроса, таймаут эмбеддинга запроса,
лимит символов документа, размер батча.

**Ответ AI.** Эти настройки готовят текстовый ответ по API и в подсказке
шапки не рисуются. В подсказке видны только элементы гибридного поиска
в обычных секциях. Число источников из поиска и из базы знаний,
области базы знаний, промпт, модель (пусто — модель aiagent), кэш,
лимит запросов в минуту, группы. Пустой список групп — все
авторизованные сотрудники; администратор видит ответ всегда.

**Статус.** Эмбеддер и его размерность, число векторов против документов
OpenSearch, очередь. Кнопка «Проверить поиск» показывает ранги BM25,
kNN, итог RRF и выдачу после прав.

## Ограничения

- Один вектор на документ. Длинный текст обрезается (`doc_text_limit`).
- Смарт-процессы и правки телефонов, которые не порождают событие
  обновления в opensearch, попадут в векторы вместе с ближайшим
  переиндексом opensearch.
- Эмбеддинг запроса — вызов API. Повтор того же текста берётся из кэша.
  Если провайдер не успел, выдача остаётся BM25.
- База знаний aiagent ищется своими эмбеддингами (MySQL), не индексом kNN.
- Права CRM и инфоблоков применяются после слияния, как в opensearch.
  Скрытая от сотрудника сущность не попадает ни в подсказку, ни в ответ.
